# Tradewinds

A dashboard and trading bot for [Tradewinds](https://tradewinds.kibb.io/), the headless Age of Sail trading game played over an HTTP API. Sign in, found or pick a company, watch your ships, trade at port order books, and let the fleet autopilot run your ships, pick lanes and buy more ships for you.

Talks to `https://tradewinds.kibb.io/v1` (game guide: `/skill.md`, spec: [docs/kibb-openapi.json](docs/kibb-openapi.json)).

## Tech Stack

- **Next.js 15** with React 19 and TypeScript
- **Tailwind CSS 4** for styling
- **Base UI** for unstyled, accessible components
- **pnpm** as the package manager

## Getting Started

```bash
pnpm install
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000), register or sign in, then found or pick a company. That's the whole setup: no database, no env vars.

- Your passphrase goes straight to kibb.io and is never stored. Sign-in gets a 90-day player key, kept in an httpOnly cookie.
- Picking a company mints a company-bound API key, saved server-side in `.kibb/store.json` (gitignored) so the autopilot can trade while no browser is open.
- Logins are rate limited (12 a minute), so don't hammer the sign-in form.

| Variable | Description | Default |
|---|---|---|
| `KIBB_API_URL` | Game API base URL | `https://tradewinds.kibb.io` |
| `KIBB_STORE_DIR` | Where keys and autopilot settings are kept | `.kibb/` |
| `TOPSTATS_API_KEY` | TopStats token for naming new ships after Discord bots | bundled names |
| `COOKIE_SECURE` | Force the session cookies' `Secure` flag (`true`/`false`) | on when the request came over HTTPS |

## Fleet autopilot

Runs inside the Next.js server; start and stop it from the dashboard. It puts every ship under its own agent and keeps them busy:

- **Lanes.** A lane is one leg of work: sail to a source, load, sail to a destination. Three kinds: **charter** (goods for charters there, live ones and gossiped ones, counted at the chance they're still open), **market** (goods sold to the destination's buyers at the last bid seen there, marked down for its age), and **freight** (Merchant Adventurers lots at the ship's own port). Spare hold and cash are filled with other goods the source sells that the destination wants, and freight lots for the same destination. Costs: the ask with price impact, customs (the live figure from the last book or port view), the remittance fee, berth dues for the stay loading at the source and the one at the destination (the port's posted daily rate, 10 Cr a day until one is seen, at least 6 game hours a stay), and the cargo pirates are expected to take (live zone piracy, net of marques, patrols and the ship's guns; pirates go for the richest prizes, so a valuable load draws more raids and an empty ship almost none). The chance of pirates taking the ship itself is charged to the leg at the hull's replacement value. Storms are charged the same way. Each leg rolls for the zone it ends in at the catalog's storm odds per game day at sea, worse in storm season (game months 11-2, about 2 real days in every 6). A hit destroys a quarter of every stack, and a rare sinking costs the hull. Lanes through long, stormy legs (Baltic, Dogger Bank, Norwegian Trench) rank lower then, and Channel and short legs win. How often storms really strike is learned from the fleet's own voyages: each passage's exposure against the storms met, starting at half the zone's rate, doubled in storm season. On first start the fleet reads the company's 7-day event log for this, and the dashboard shows the figures. The game doesn't publish these formulas: the share a raid takes is learned from the fleet's own raids, starting at 30%. Lanes are ranked by profit per hour over the leg plus the best leg visible from the destination, so a lane ending where a paid return cargo waits beats a dead end. Loads are sized to the cash the fleet can spend when the ship reaches the source (see Cash); reservations spread ships across charters, sources, buyers and freight.
- **Phase bonus.** Expansion charters also earn a share of the tier's completion bonus, split by base value delivered, so a ton of cannons is worth far more than a ton of provisions. The value per ton comes from the live pool over the tier's projected base value (clamped to 6-20% of base). That expected share, discounted by a setting (75% by default), counts in lane choice and buy prices. The dashboard shows each company's share of the bonus so far.
- **Hold space.** Each gun takes 2 t of hold. With guns on "auto", a ship calling at a shipyard is refitted to the count that earns most on its lane, weighing cargo room against the cargo pirates are expected to take there and the risk of losing the ship to them. In phase-1 waters that is usually none. Surplus stores above what the voyage needs are moved out and sold when the hold is what limits a load.
- **Events.** It long-polls the company's event log: a ship's agent wakes the moment it arrives, is berthed from the queue, is evicted or hit by a hazard, and a posted, filled or expired charter refreshes the world within seconds so idle ships re-plan at once. Timers remain the fallback if the feed drops.
- **World events** (setting, on by default). It reads the public world-event feed with every world refresh (once a minute, and within about 5 seconds of a world-event notice on the event log) and keeps the last 11 game days of it. A **shortage** raises the bid expected at that port for that good, and a **glut** lowers the ask there; both fade to nothing by the news' lapse (30 game hours), so lanes form toward shortages and from gluts while a ship can still get there (ports in one are tried on top of the best few buyers and sellers). How big they are is learned from the books our ships read while one is on (1.15× and 0.85× base to start), a book read since it began replaces the guess, and a price read at a shock's height is eased back as the shock fades. Every shortage brings a Governor crisis charter, listed only on its quay or as gossip hours later. Until a listing shows it, lanes count it as expected: the tons the news names (at most 350), at the crisis pay seen so far (1.25× base to start), trusted at the share of crisis charters found when looked for (60% to start), with at most one ship's load on it, less for laden rivals seen heading there; the buyer never builds a ship for one, nor counts one as a lane's onward leg. The real charter replaces it as soon as a listing or one of our ships in port shows it, and a ship already in port lists the quay again once the news is an hour old, so one that isn't there is dropped then; if a load arrives to find none, it is sold at the port's shortage bid or taken to a better market. Admiralty mobilizations are public charters, planned as soon as the listing shows them. A pirate outbreak counts in the zone's piracy until the zones are read again. A structural shift re-reads the catalog (what each port makes and imports; live customs are re-read every 30 minutes anyway), and asks from before a production collapse, or bids from before an import slump, at that port are no longer planned on. Off: no shortage or glut prices and no expected crisis charters; outbreaks, structural shifts and finding crisis charters still count. The dashboard lists the events in force, what the planner does with each, and the learned figures.
- **Sailing.** Buys up to the charter's break-even price, keeps stores at the route's safe figure (which survives one storm or pirate hit) or more on passages likely to take two or three (long ones, and in storm season), refuses water the hull isn't rated for (lane *and* sea-zone class), delivers from the roadstead when the per-ton berth lock would cost more than waiting out the base lock (several charters in one batch call), and times everything on the server's clock. A leg the server expects to starve, stores running out at sea, or a mutiny anywhere in the fleet adds a game day of stores kept in hand (up to 6; safe arrivals wear it down). Orders never match our own other companies: their resting asks and bids, found when an order of ours crosses them and they stay untouched, are left out of the prices from then on.
- **Freight.** Picks up Merchant Adventurers freight on legs it sails anyway when the reward beats the berth time it costs. A lot's reward counts only at the chance the ship arrives, and a sinking or a capture forfeits its collateral too, so freight over dangerous water is priced at that risk.
- **Convoys** (setting, on by default). Just before a ship sails, it looks for our other ships bound the same way: it joins one of our convoys forming at that port for the same destination, or forms a private one (as flagship, from the roadstead) when another of our ships will be ready to leave the same way within 6 game hours. In a convoy pirates board just one ship and guns are pooled, so each of n ships' expected piracy losses (cargo, and the ship itself) roughly fall by (n-1)/n; it convoys only when that, less the extra storm loss of the slower and later passage, beats what the wait costs the ship's time, and only with ships of similar speed (a convoy sails at its slowest). Safe water and empty passages sail alone, and so does a ship whose port's forming convoys can't all be read. Convoy departures aren't checked for stores, so a ship's stores are checked against the convoy's pace and the wait in port when it joins or forms one, and again on every pass while it waits (a slower ship may join later): short, it moves provisions from its cargo into the stores, or leaves to top up and joins again or sails alone, unless a policy may count on the consorts and the bare need is still covered. While waiting in a convoy a ship does nothing else; it sails with the others at the set time.
- **Your policies.** The autopilot never buys insurance, but a policy you bought for a ship binds its next voyage: it loads only for the policy's port and sails nowhere else (sealed freight that would otherwise miss its deadline wins, logged as voiding the policy), never sells at the policy's origin (that cuts the cover), keeps its guns, and stays in a convoy whose consorts the policy may count on. The dashboard asks before you detach an insured ship from a convoy.
- **Cash.** Buying is paid from the port's banking region; it remits from other regions on demand (instant, at the live ACH fee) and always keeps the reserve in the home region. A load is planned on the cash that will be spare when the ship reaches its source: cash in hand, less what our other ships' loads will spend first, plus a share (60% by default, setting) of what our ships at sea are due to be paid before then. That covers charter pay and sales at the planned price, and freight reward and collateral, less the remittance fee to the source's region; cargo held for a re-post isn't counted. At the source, just before buying, the load is planned again from there with the cash there is then: bigger when deliveries paid meanwhile, the best smaller mix when the cash went elsewhere (setting, on by default). A ship never spends cash another ship's load counts on, unless cash due lands before that ship buys; a ship at its source keeps first call on the share of its own planned load that was planned on cash in hand (less what a part dearer than planned has already taken), and only the cash due it counted on, or growth beyond its plan, must leave the others' loads alone. A load that counted on cash due not yet landed waits for it in the roadstead rather than sail with less than the planner's minimum load. The log says when a load was re-sized and the panel counts them. A ship waiting for cash tries again as soon as another delivery pays, or a re-sized load frees some.
- **Letters of marque** (off by default). Every 5 minutes it weighs each sea zone: rival cargo passing through over the last game day, from quay sightings and (with rival intel) public insurance policies and convoys, or the sailings already announced for the next day if more (a convoy counts once, at its richest member's cargo), against the cost of a one-day marque and the extra piracy our own ships would face there. It sponsors the best one only when there are at least 3 laden rival passages a day, the expected prize is at least 1.5 times cost plus our own extra losses, and the spend stays within the budget (1,000 Cr in any 24 hours by default, the marque sized down to fit). The zone's 5,000 bps marque cap is respected.
- **Rival intel** (setting, on by default). Besides sailings at ports where we have presence, it reads the public insurance list (which ship of which company means to sail where, with how much cargo declared; closed policies give arrivals and sinkings), public convoys (schedule, hulls, guns), the expansion board (who delivered how much to which charter: each charter's growth less our own deliveries, named when exactly one rival's contribution grew by that much) and the hourly leaderboard (net worth, so earning rate). Sources are tied together (company id to name, ship id to name) only on unambiguous matches. The planner takes from a charter's room what rivals due there before us are likely to deliver (by their declared cargo or their past deliveries there; laden ones of unknown cargo take a share as before); a laden rival likely to deliver to a stalled expansion charter before it lapses lowers the odds of the richer re-post (lanes count on it less, and below 40% the fleet won't let the posting lapse for it). A laden rival's sailing notice re-runs that within seconds. The underwriter skips an insured whose own sinkings on a lane (8 closed policies at least) exceed Lloyd's bound. About 1.5 extra reads a minute. Off: quay sightings only, as before.
- **Underwriting** (off by default). Every minute it reads other companies' open policies and writes slices on those someone other than you has already partly covered (in practice Lloyd's, which writes only when the premium is at least 1.25 times its expected loss + 25 bps, so that policy's loss is at most (premium - 25) / 1.25). The edge over that bound must reach the minimum (150 bps by default, so premiums from about 650 bps). Uncovered policies are left alone: young ones wait for Lloyd's review, older ones were declined. Slices are capped per policy (3,000 Cr) and in total escrow (5,000 Cr), paid only from spare cash above each region's floor; policies older than 36 game hours are skipped as likely at sea. Our own companies' policies are read in full (page by page) so none is taken for Lloyd's cover; when they can't all be listed, it writes nothing that round. A sinking costs the whole slice, so keep the budget to what you can lose.
- **Expansion re-posts and stalls.** Expansion charters are re-posted when they lapse (every 30 game days in Phase 2, 12 real hours, all of a tier's at once), so their expiry doesn't end the work: lanes keep planning on them, and the buyer counts on them for as long as the tier lasts at its recent pace. A posting nobody delivers to comes back richer (about +25% pay on 75% of the tons; the autopilot learns the real figures when it sees one), and the higher pay stays for later postings. The guide calls a posting stalled while under a tenth of its expected pace (its tons spread over its window) is delivered, and says any rival delivering cancels the escalation, "so waiting rarely pays". The autopilot judges that per posting: the pace line runs from the posting's listed start (else its lapse less the usual window), and any other company's delivery into it ends the stall for that posting, our own other companies' included (the server counts them as other companies). Whether our own small deliveries cancel it isn't published (the feed has shown a posting with only 1.5% delivered that didn't escalate), so it starts safe: ours are taken to cancel it, and re-posts teach it otherwise. A posting only our ships delivered to, still under the line late in its window, that re-posts richer is a confirmation; after 2 in a row, a ship may deliver into a posting being let lapse when the whole of its load for it keeps it under 80% of the line, and one such re-post that doesn't escalate switches that off again (each is logged and the record is saved). So for each stalled posting the fleet makes one call (setting, on by default): let it lapse when the chance it escalates × the extra pay × the tons it expects to put into the re-post (its recent flow there over a posting, loads already bound for it that can wait for it) is at least 1.25 times what waiting costs (loaded ships landing first or already holding, at their earning rate and the cash they tie up; their tons the smaller re-post can't take, sold at the bid instead; part of the margin on its own flow there until the lapse and on loads it shuts out, those landing more than 4 real hours early), and keep doing so while it covers that cost. The odds come from stalls seen lapse, each charter's rival record (how often rivals broke its stalls, from the public contributor board, pooled with the tier's) and laden rivals seen bound for its port (likelier from a port selling the good or a company seen delivering there). Under 20%, a likely rival delivery first, an AI "deliver" call, the season ending before the re-post, a tier that may complete first, or loads of ours (into any of the tier's postings) that would complete it, or a loaded ship that would wait over 4 real hours: it delivers. While it lets a posting lapse no ship delivers into it (beyond such a load, once learned), the tons a ship's load plans into it that land early wait in the roadstead (never planned more than 4 real hours early; the rest of the good goes where it was planned, and leftovers are never held), ships take other work until a run lands just after the lapse, and holders deliver at once when a rival's public delivery notice shows up. A re-post that stalls again is just another stalled posting. "Always hold" (off by default) and an AI "wait" force it in a posting's last 4 game hours whatever the math says. The dashboard shows each charter's state, the fleet's call with its numbers, rival deliveries seen and the tier's ETA.
- **Scarce cash.** When cash is what limits the fleet (a ship waits for it, or what's spare wouldn't fill half a load), lanes are charged for the money their loads tie up, at half the fleet's own return on cash, so high-margin loads win over thin ones that lock up the same money. Once the tier is 90% done or due within 2 hours, and for an hour after it turns over, the buyer keeps a share of spare cash back (40% by default) for the next tier's charters, which nobody can reach at first. Hulls, marques and underwriting never count on cash due.
- **Season end.** Once the operators announce it (`season_planned_end_at`; the panel shows it), only work that lands at least 30 minutes before the end is planned: legs, freight lots and leftovers carried elsewhere. A completion bonus counts only for a tier that can finish in time; no hull is built that can't pay back before the end, nor any in the last 12 hours, and no marques then either; in the last 3 hours goods are never sold under base price (they count at base in net worth); a stalled posting whose re-post would come after the end is delivered to.
- **World pause and notices.** While the operators pause the world (`world_paused`), ships wait without trying anything, housekeeping only reads the clock every 30 s, and nothing is bought, sold, remitted or built; on resume the world is read again and every ship looks again. The panel and header show the pause. A critical server announcement shows as a banner on the panel, and a header badge, for a day.
- **AI support (Claude)** (off by default; switch it Off / Shadow / Live on the fleet panel, needs `ANTHROPIC_API_KEY` in `.env.local`). Claude acts as strategist (Opus 5.5 by default, or Sonnet 5.5 at half the price; low thinking effort by default, which is most of a call's cost): every 60 minutes by default (half that near a phase turnover; a routine call is skipped when nothing important changed), and soon after a phase change, a stall escalation, a lost ship or a trip far below its estimate, it reads a digest of the fleet and the world (each ship's guns, stores and cash for its next load; sea zones with their piracy, rival traffic and our exposure; yards with their last quotes and the buyer's best options; the budgets; every setting with the range it may set it to; rivals due at open charters; and its own directives in force with what became of them) and answers with directives. Live, they apply until they lapse (15-180 min), and every autopilot check still runs on them:
  - **Settings:** any setting but its own (its mode, caps, model, effort and cadence can't even be named), within the range the digest shows (spend ceilings yours, the reserve only raised), under hard floors applied wherever settings are read: max ships, the marque budget and the underwriting budgets never above yours, the home reserve only ever raised (the home floor still covers 1.5 days of bills), no ship buying without the key's `infra_manage`. A setting you change wins at once for the rest of its advice.
  - **Bans and bias:** bans on ports (no loading, delivering or selling there), sea zones (no passage, laden or empty), goods, charters, or public charters rivals are due at first; and a bias of 0.5-1.5x on lane ranks by either end, zone, good, charter or lane (only lanes that already pass every check). Bans apply to new plans only: cargo aboard is never stranded.
  - **Stall calls** on stalled expansion charters (let it lapse for the re-post near the end, or deliver now).
  - **Ship orders,** one per ship: take a given lane or fill a given charter at its next plan (when one passes every check; else it plans as usual), go to a port (loads from there only, or sailing there empty over a rated route no ban rules out), hold in the roadstead (at most a third of the fleet; held ships count as idle for the tripwire), or drop a planned lane nothing was bought for. A policy you bought, sealed freight and cargo aboard always come first.
  - **The buyer:** hold, forbid classes, or one build of a given class at a given yard through all the buyer's checks (payback limit, cash after loads, max ships, the season); it needs a ship of ours there, or a factor with yardFactor on.
  - **Marques and patrols** (at most 2 an answer): checked against the zone's cap and the season, paid from spare cash after the fleet's loads (never by remitting), within what the marque budget (yours, shared with auto-marques) has left over the last 24 hours, for a term no longer than its advice. An issued one can't be withdrawn: it runs its term even when the advice is cleared. Set the marque budget to 0 to forbid them.

  What can't be done is refused and comes back to it as a fixed status code (never the game's own wording); every outcome is logged. Shadow logs the same answers without applying them. Ships, charters, lanes and rivals appear to it only as aliases, and game notices only as fields Claude Haiku 5.5 extracted, so nothing other players write reaches it. Spend is capped per UTC day and in total ($2 and $180 by default; a call whose worst case could pass a cap is skipped); half the fleet idle or held under its directives for 20 minutes clears them (marques and patrols already issued run on); if trips under its advice earn under 80% of trips without, it drops back to shadow. Every decision is kept in MongoDB (`ai_decisions`); the dashboard shows the spend, every directive in force with its reason and status, and why. The planner also learns three figures on its own: how often a stalled posting stays stalled to its lapse, and how often rivals break a stall, per charter, and how fast remembered bids drift; and it discounts charters by what rivals due there first are likely to deliver.
- **Buying ships.** Wherever the fleet has presence at a shipyard (a ship there, or a Resident Factor) it quotes every allowed class, scores each by payback hours on its best lane net of the extra fleet upkeep, builds the quickest payback within your limit (unarmed unless guns are on "full"). With no presence at any yard, it prices a build at the yard nearest the fleet's work from the last quotes it saw; if that pays back (fee included) it hires a Resident Factor there (750 Cr), builds, and dismisses the factor straight after, so building never waits for a ship to pass by and no factor salary runs on (setting, on by default; never past the company's 12 factors). A new hull's cargo room counts the stores its first lane really needs (a big crew on a long passage takes several tons). When it is cheaper by at least 300 Cr it builds from its own materials instead of turnkey (setting, on by default): it buys what the yard's quote lists on that port's own market into a warehouse lease there (IOC bids capped a little over the quote's per-ton price, customs paid), builds with `byom`, which skips the yard's 15% markup on materials, and shrinks the lease back after; materials it couldn't finish buying stay in the warehouse for the next try. New ships are named after random Discord bots from the [TopStats](https://topstats.gg) API (set `TOPSTATS_API_KEY`), or a bundled list without a key.

Settings (cash reserve, minimum margin, max ships, max payback, allowed classes, guns, phase-bonus weight, storm losses counted, freight, yard factor, own-materials builds, rival intel, let stalled postings lapse, always hold for re-post, world events, cash kept back near a new phase, re-sizing loads at the source, cash due counted, marques and underwriting with their budgets) apply live; the dashboard sends only the fields you changed. The panel also shows where each ship's time goes (laden, empty at sea, in port, idle), its Cr/hour, and each finished trip's planner estimate against what it made. The home-region reserve never drops below 1.5 game days of fleet upkeep (sprawl, factors and oceanic hulls, or what the ledger shows was billed if more), whatever the setting, and every other region keeps 200 Cr for dues and stores; each region also keeps 1.5 days of its warehouse rent, and stores to sail safely may dip into all of that. Upkeep is billed from home, so every 10 minutes the autopilot tops the home vault up to its floor from the other regions' spare. Auto-remit for bills (the company page) is only read and reported, never changed: off, the log says a region that can't cover its own bill meets the bailiff. The enabled flag persists, so a running autopilot resumes when the server restarts, and so does its progress: each ship's lane and whether its cargo is aboard, its sell floors, trips, stats, purchases, the log, the event cursor and what the world model had learned (prices, stalled charters, tier pace, rival intel: sightings, public policies and convoys, rival deliveries per charter (from the expansion board), net-worth history; per expansion charter, how often rivals broke its stalls and our own flow into it; the postings being let lapse; world events, and what they did to prices and crisis charters; the storm record), and the count of loads re-sized at their source. That is saved to MongoDB when `MONGODB_URI` is set (`fleet_snapshots`, one document per company, and `fleet_trips`, every finished trip), and always to `.kibb/fleet-<company>.json`; on start the newer copy wins. Trips, loads, deliveries and buyer actions save at once, everything else at most every 15 s. On SIGINT/SIGTERM the server saves before exiting when run with `NEXT_MANUAL_SIG_HANDLE=true` (the pm2 config sets it). A lease file in `.kibb/` stops a second process on this machine (another server or the CLI) from running the same company; with `MONGODB_URI` set a lease document (`fleet_leases`) does it across machines too (while the database can't be reached, the file alone holds, and start-up never waits on it). Don't give manual orders to ships while it runs.

To run it without the dashboard (e.g. on a server):

```bash
pnpm exec tsx --env-file=.env.local src/workers/kibb-fleet.ts
```

with `KIBB_API_KEY` (a company-bound key) in `.env.local`. See the header of [src/workers/kibb-fleet.ts](src/workers/kibb-fleet.ts) for its settings. Mind the key's lifetime: `POST /v1/auth/login` keys last 24 h unless you pass `ttl_seconds` (up to 31,536,000, a year), and `create-key` with handle and passphrase and no `ttl_seconds` never expires. The autopilot stops when its key expires; it warns in the log at 7 days, 1 day and 1 hour left (from `whoami.expires_at`; each once, restarts included). In the dashboard the company key is renewed by itself in its last 7 days while you are signed in (the running autopilot switches to the new key without a restart); the panel warns in that last week and the header in the last 3 days, and an autopilot that couldn't be resumed after a server restart says why on the panel.

## Pages

Every page works on a phone: below 1024 px the sidebar becomes a drawer behind the header's menu button, panels stack, filters wrap and wide tables scroll sideways.

| Route | Description |
|---|---|
| `/login`, `/register` | Player sign-in and registration |
| `/companies` | Pick or found a company |
| `/dashboard` | Cash, fleet, phase-2 progress, leaderboard; fleet autopilot controls, per-ship lanes, purchases and log; ships, vaults, charters |
| `/map` | Live map: ships placed along their routes, sea lanes, ports, piracy per sea zone, rival ships at their estimated positions |
| `/rivals` | Rival companies (net worth, earning rate, ships, lanes, declared cargo, charters they feed), rival ships and voyages from quay sightings, public policies and convoys with where each probably is, the charters rivals feed (stall odds), rival traffic per sea zone with the marque verdict, auto-marque settings and your marques |
| `/events` | Live company event feed (long poll) and the world events history |
| `/fleet` | All ships; shipyard quotes and builds (turnkey or own materials), names from TopStats |
| `/fleet/[shipId]` | Ship detail: dock/roadstead, depart with route and stores check, stores in/out, guns, warehouse load/unload, charters and freight here, insurance, convoys |
| `/convoys` | Convoys: organise, join (as escort), leave; approve, reject, kick, invite |
| `/market` | Order books; IOC or GTC orders (ship or warehouse), resting orders and cancels, fills, batch orders |
| `/contracts` | Charters (deliver, batch deliver), freight (accept, batch accept, deliver, issue your own) |
| `/warehouses` | Leases, inventories, load and unload ships |
| `/treasury` | Vaults and escrow, ACH rates, remittances, ledger |
| `/insurance` | Your policies, slices you underwrite (with collateral and premium share), the open market with each policy's cover, Lloyd's-implied loss bound and edge; insure a voyage with the lane's past premiums as a guide, underwrite (batch) |
| `/futures` | Hub futures: create (batch), accept (batch), settle |
| `/ports`, `/ports/[id]` | Every port with filters and your presence; berths, dues, book, gossip, sailings, factor hire, lease, port events |

| `/leaderboard` | Season leaderboard (your rank), hall of fame, company lookup, expansion progress |
| `/company` | Profile, auto-remit settings, Resident Factors, bankruptcy |
| `/account` | Your API keys (revoke one or all) and passphrase change |

## Project Structure

```
src/
├── app/
│   ├── (auth)/              # Sign-in, register, company picker
│   ├── (game)/              # Every game page (see Pages)
│   └── api/kibb/            # Session routes, autopilot control, and /v1 proxy to the game API
├── components/kibb/         # Shared panels, tables, badges
├── instrumentation.ts       # Resumes enabled autopilots on server start
├── lib/kibb/
│   ├── client.ts            # Typed API client (Idempotency-Key, retries, 429 handling)
│   ├── fleet/               # Autopilot: world model, lane planner, ship agents, manager, ship names
│   ├── fleet-registry.ts    # In-process autopilots, one per company
│   ├── store.ts             # .kibb/store.json
│   ├── schema.ts            # Every API schema, generated: node scripts/gen-kibb-schema.mjs
│   └── types.ts             # Hand-written API types used by the autopilot
└── workers/kibb-fleet.ts    # CLI for the autopilot
```

The browser never sees a company key: `/api/kibb/v1/*` forwards to the game with the active company's stored key, and refuses key management, company founding and bankruptcy. Those go through dedicated routes: account actions use the signed-in player's key, changing company settings mints a two-minute `account_manage` key and revokes it straight after, and bankruptcy needs the company's name typed back and stops the autopilot first. Passphrases are passed through, never stored. It, and the autopilot route, act only for a signed-in player who owns the selected company (checked against the game, cached for 5 minutes); the company cookie alone does nothing.
